> `$ARGUMENTS` = 리포트 주제나 범위.

## 파일

- HTML 파일 하나로 만든다. 마크다운(.md)으로 쓰지 않는다.
- 이미지는 리포트 옆 `assets/` 폴더에 두고 상대경로로 참조한다.

## 디자인

- 토스 디자인 시스템(TDS) 스타일, 폰트는 Pretendard.
- 섹션이 많으면 왼쪽에 고정 사이드바 목차를 둔다. 하위 절까지 링크하고, 스크롤 위치에 맞춰 현재 항목을 강조한다. 좁은 화면에서는 사이드바를 숨기고 본문 상단 목차로 대신한다.

## react-grab

리포트를 브라우저에서 보면서 요소를 골라 수정 요청할 수 있게 `<head>` 에 react-grab 을 넣는다.

```html
<script src="https://unpkg.com/react-grab/dist/index.global.js" crossorigin="anonymous"></script>
```

- 리포트를 넘길 때 사용법을 한 줄 덧붙인다: 요소에 마우스를 올리고 ⌘C(그 외 OS는 Ctrl+C)를 누르면 요소 정보가 복사되니 그대로 붙여 넣어 수정을 요청하면 된다.
- CDN 스크립트라 오프라인에서는 이 기능만 빠진다. 나머지 렌더링은 오프라인에서도 되어야 한다.

## 다이어그램

- 구조도/계층도/관계도/흐름도 같은 시각화는 전부 `diagram-design` 스킬로 인라인 SVG를 만든다.
- `<pre>` 에 ├ └ ─ → 같은 문자로 트리, 박스, 화살표를 그리지 않는다. `<pre>` 는 JSON, SQL, 의사코드처럼 실제 코드나 데이터 원문에만 쓴다.

## 코드 블록

- JSON, SQL, 코드, 의사코드, HTTP 요청/응답에 구문 하이라이팅을 적용한다.
- 외부 라이브러리 없이 페이지 안 스크립트로 처리한다.

## 에러 로그와 콘솔 출력

에러 응답, 스택 트레이스, 콘솔 출력은 한 줄로 붙이지 않고 어두운 터미널 스타일 블록으로 보여준다.

- 헤더 바에 요청 메서드/경로(또는 명령)와 상태 배지(예: `400 Bad Request`, 실패는 빨강).
- JSON 은 들여쓰기로 펼치고 키/문자열/숫자/구두점 색을 구분한다.
- 긴 메시지는 의미 단위로 줄을 나누고, 핵심(문제 컬럼/값, 원인 옵션, 에러 코드)에 배경색 하이라이트를 준다. 2~3색까지 쓰고 블록 아래에 색 범례를 붙인다.
- 줄 나눔이나 생략처럼 원문을 가공했으면 캡션에 적는다. 값을 지어내거나 바꾸지 않는다.

## 화면 흐름

- 앱/웹 화면, 웹뷰, 외부 서비스 연동 화면은 글로만 설명하지 않고 원문 문서나 실제 화면 캡처를 잘라 넣는다.
- 캡션에 출처(문서명, 쪽수)를 적는다.

## 시스템 연동

구간마다 누가 누구에게 보내는지, 메서드/주소/인증, 요청 본문, 응답 본문을 예시로 보여준다.

- 예시 값은 가능하면 실제 데이터(문서, 코드, 수집 데이터)에서 가져온다.
- 비밀값(키, 토큰)은 가린다. 실제 응답을 봐야 아는 값은 `<...>`, 제안 단계의 필드는 `(안)` 으로 표시한다.

## 구현 설계

- 앞으로 구현될 것이 분명한 기능은 "무엇을 해야 하는지"에서 멈추지 않고 "어떻게 구현할지"(API 안, 데이터 모델, 처리 흐름, 예외 상황)까지 쓴다.
- 제안 전에 원문 문서의 권장안/제한 사항과 현재 코드베이스(필요하면 같은 PC의 다른 프로젝트)의 비슷한 기능/패턴을 먼저 확인하고, 그 결과를 근거로 적는다.
